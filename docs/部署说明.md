# WTCS 部署说明（Linux）

> 适用：把本系统部署到 Linux 服务器（内网生产环境）。
> 架构规划与投产标准见《投产架构规划.md》；本文档只讲怎么装、怎么跑、怎么维护。

---

## 1. 环境要求

| 项 | 要求 |
|----|------|
| 操作系统 | Ubuntu 22.04+ / CentOS Stream 9 / 麒麟 / 统信 UOS（x86_64 或 ARM64） |
| Python | 3.11+（代码用到 3.10+ 类型语法） |
| Node.js | 仅构建前端需要（20+）；可不在服务器装，本机构建后上传 `frontend/dist` |
| 反向代理 | nginx（托管前端 + 反代后端，含 WebSocket） |
| 端口 | 后端 8000（仅监听回环），nginx 80/443 对外 |

目录规划（推荐）：

```
/opt/wtcs/
├── backend/            # 后端代码
│   └── data/           # ★ 全部运行数据：wtcs.db / backups/ / branding/ / logs/
├── frontend/dist/      # 前端构建产物
└── venv/               # Python 虚拟环境
```

## 2. 安装步骤

### 2.1 后端

```bash
sudo mkdir -p /opt/wtcs && sudo chown $USER /opt/wtcs
# 上传代码后：
cd /opt/wtcs/backend
python3 -m venv /opt/wtcs/venv
/opt/wtcs/venv/bin/pip install -r requirements.txt \
  -i https://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

### 2.2 前端构建（本机或 CI）

```bash
cd frontend
npm ci
npm run build        # 产物在 frontend/dist
# 上传 dist 到服务器 /opt/wtcs/frontend/dist
```

### 2.3 环境变量

| 变量 | 默认 | 投产要求 |
|------|------|----------|
| `WTCS_JWT_SECRET` | 开发默认值 | **必须**改为随机长字符串 |
| `WTCS_FORCE_SIMULATION` | `true` | 真机上线改 `false`，并核对 `config/subsystems.yaml` |
| `WTCS_CORS_ORIGINS` | localhost:5173 | 改为正式访问地址（如 `https://wtcs.example.com`） |
| `WTCS_TELEMETRY_HZ` | `10.0` | 一般不动 |
| `WTCS_TIMEZONE` | `Asia/Shanghai` | 一般不动 |

### 2.4 systemd 服务

`/etc/systemd/system/wtcs.service`：

```ini
[Unit]
Description=WTCS 测控系统后端
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/wtcs/backend
Environment=WTCS_JWT_SECRET=请换成随机长字符串
Environment=WTCS_FORCE_SIMULATION=false
Environment=WTCS_CORS_ORIGINS=https://wtcs.example.com
ExecStart=/opt/wtcs/venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5
# 资源保护（可选）
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now wtcs
systemctl status wtcs        # 确认 active (running)
curl http://127.0.0.1:8000/api/health   # {"status":"ok",...}
```

> 后端只监听 127.0.0.1，外部流量全部经 nginx 进入。

### 2.5 nginx

```nginx
server {
    listen 80;
    server_name wtcs.example.com;

    root /opt/wtcs/frontend/dist;
    index index.html;

    # 后端 API + WebSocket（遥测长连接）
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;    # WebSocket 必需
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3600s;                  # 遥测 WS 长连接保活
    }

    # 前端 SPA：所有非文件路径回退到 index.html（刷新 /subsystems 等不 404）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源长缓存（构建产物带 hash）
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

HTTPS（投产必须）：用 certbot 或内部 CA 签发证书，标准 443 server 块 + 同上反代即可。

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 3. 验证清单

部署后按序检查：

- [ ] `curl http://127.0.0.1:8000/api/health` 返回 ok
- [ ] 浏览器打开 `http://服务器地址/` 出现登录页（有品牌 Logo）
- [ ] 登录后总控台风速等读数在动（说明 WebSocket 遥测链路通）
- [ ] 按 F5 刷新 `/subsystems` 等子路径不 404（SPA 回退生效）
- [ ] 大屏 `/screen?kiosk=1` 正常全屏显示
- [ ] 系统设置 → 备份：手动触发一次备份，确认 `data/backups/` 生成文件

## 4. 数据与备份

**全部运行数据都在 `/opt/wtcs/backend/data/`**：

| 子路径 | 内容 |
|--------|------|
| `wtcs.db` | SQLite 主库（业务/遥测/审计/设置） |
| `backups/` | 系统自带定时/手动备份产物（设置页可下载、可恢复） |
| `branding/` | 后台上传的品牌 Logo（删除即回退内置默认） |
| `logs/` | 轮转运行日志 |

建议加一层异地备份（crontab 示例，每天 02:40 同步到 NAS）：

```bash
40 2 * * * rsync -a --delete /opt/wtcs/backend/data/ /mnt/nas/wtcs-data/
```

恢复演练：系统设置 → 备份 → 上传备份文件恢复；或停服后直接替换 `wtcs.db`。

## 5. 升级流程

```bash
# 1. 备份（必做）
systemctl stop wtcs
cp -a /opt/wtcs/backend/data /opt/wtcs/data.bak.$(date +%Y%m%d)

# 2. 更新代码与依赖
cd /opt/wtcs/backend && git pull   # 或上传新代码覆盖
/opt/wtcs/venv/bin/pip install -r requirements.txt   # 有新增依赖时

# 3. 更新前端
# 本机 npm run build 后上传 dist 覆盖 /opt/wtcs/frontend/dist

# 4. 启动并验证（数据库迁移在启动时自动幂等执行）
systemctl start wtcs
curl http://127.0.0.1:8000/api/health
```

> 数据库结构变更通过启动时的幂等迁移自动完成（新增列/表），无需手工 SQL。

## 6. 常见问题

| 现象 | 排查 |
|------|------|
| 页面空白 | 看浏览器控制台；多数是 `dist` 未更新或 nginx `try_files` 缺 `/index.html` |
| 登录后数据不动 | WebSocket 没通：检查 nginx 的 `Upgrade`/`Connection` 头与 `proxy_read_timeout` |
| 刷新子路径 404 | nginx SPA 回退未配置 |
| 502 | 后端没起：`systemctl status wtcs`，日志看 `backend/data/logs/wtcs.log` 与 `journalctl -u wtcs` |
| 时钟不准/曲线时间错乱 | 服务器未同步 NTP：`timedatectl` 检查，投产要求接入现场 NTP |
| 中文乱码 | 系统 locale 需为 UTF-8（`localectl set-locale LANG=zh_CN.UTF-8` 或 en_US.UTF-8） |

## 7. 大屏与等候区屏配置

无需安装任何软件，显示设备浏览器开机自启打开对应 URL 即可：

| 场景 | URL |
|------|-----|
| 主控室大屏（全系统总览） | `/screen?kiosk=1&mode=overview` |
| 多屏矩阵切片（电视 A/B） | `/screen?kiosk=1&mode=matrix&part=1/2` 与 `part=2/2` |
| 等候区轮播 | `/screen?kiosk=1&rotate=30` |
| 客户等候区排程公示（脱敏） | `/screen?kiosk=1&mode=schedule&privacy=1` |
| 控制室排程调度（完整） | `/screen?kiosk=1&mode=schedule&privacy=0` |
