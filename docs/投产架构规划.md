# WTCS 联调 · 试运行 · 投产架构规划

> 面向阶段：现场联调 → 试运行 → 正式投产。
> 本文档定义目标架构、基础设施要求、数据架构与验收标准；部署操作细节见《部署说明.md》。

---

## 1. 现状架构（建设期）

```
浏览器（操作员/客户/大屏）
   │  HTTP + WebSocket（/api/ws/telemetry）
   ▼
FastAPI 后端（uvicorn :8000）
   ├─ 适配器层：sim 仿真适配器 ×12 子系统（real 适配器为预留骨架）
   ├─ SQLite（backend/data/wtcs.db，WAL）：业务数据 + 遥测 + 审计
   └─ 配置：backend/config/subsystems.yaml（mode: simulation | real）
前端：React + Vite（dev :5173，构建产物 frontend/dist）
```

建设期全部为仿真模式（`WTCS_FORCE_SIMULATION=true`），页面顶部常驻「建设期全仿真」徽标。

## 2. 投产目标架构

### 2.1 总体分层

```
┌─────────────────────────────────────────────────────────────┐
│ 呈现层   操作员工作站 · 主控室大屏 · 客户等候区屏 · 客户门户      │
├─────────────────────────────────────────────────────────────┤
│ 应用层   WTCS 后端（API / WS / 命令仲裁 / 试验执行 / AI 巡检）    │
├─────────────────────────────────────────────────────────────┤
│ 数据层   TSDB（监控慢数据） · Run 文件库（HDF5） · 业务库        │
├─────────────────────────────────────────────────────────────┤
│ 采集层   OPC UA / TCP 适配器 → 边缘采集（断网续传）              │
├─────────────────────────────────────────────────────────────┤
│ 现场层   PLC / 变频器 / 天平 / 压力扫描阀 / 声学阵列 / 安全连锁    │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 关键架构决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 快慢数据分流 | 监控慢数据（1~100Hz）进 TSDB；测量原始高频（kHz）按 Run 存 HDF5/Parquet 文件，库内只存元数据 | 风洞/台架行业标准做法（NI VeriStand、Dewesoft 同构）；数据库不承担高频原始流 |
| 时序存储 | TDengine（推荐）或 TimescaleDB 替代 SQLite 遥测表 | 10Hz×12 子系统 ≈ 每日 1~2 亿行，SQLite 不适合长期原始时序；TDengine 压缩比 10~50 倍 |
| 业务数据 | 保留 SQLite（用户/项目/订单/排程/审计/设置） | 量级小、事务性访问，SQLite+WAL 完全胜任 |
| 分层降采样 | 原始 10Hz 留 7~30 天 → 1s 聚合留 12 个月 → 1min 聚合留 10 年 | 无限保留原始数据无分析价值且不可持续 |
| Run 归档 | 试验结束打包：原始文件 + 配置快照 + 元数据 + 报告，迁冷存储 | 客户交付单元 = Run 数据包，而非库查询 |
| 命令仲裁 | 保留现有单实例仲裁（执行互斥锁 + 审计 + 权限） | 测控系统严禁多实例并发下发命令 |

### 2.3 网络分区（安全）

参照 IEC 62443 的分区理念，最小落地为三网隔离：

```
控制网（192.168.10.x）   PLC/变频器/天平/安全连锁 —— 不路由出外网
   │  仅 WTCS 服务器双网卡接入（或经工业防火墙）
数据/办公网              WTCS 服务器 ↔ 操作员站 / 大屏 / 内部用户
   │  防火墙 + 反向代理
DMZ / 客户访问区         客户门户、客户等候区屏 —— 只读、按订单隔离
```

- 控制网不出机房，WTCS 服务器是唯一的跨区节点
- 客户侧只暴露 HTTPS 门户，客户角色服务端数据隔离（已实现，按 `customer_username` 过滤）
- 客户等候区大屏使用 `privacy=1` 排程公示模式（服务端字段级脱敏，已实现）

## 3. 基础设施（Infra）要求

### 3.1 服务器

| 用途 | 配置建议 | 说明 |
|------|----------|------|
| WTCS 应用服务器 | 8C / 32GB / 2×1TB SSD RAID1 | 后端 + TSDB + 业务库；双网卡（控制网+办公网） |
| Run 数据存储 | NAS / 服务器挂盘，≥16TB HDD RAID6 | 高频原始文件与 Run 归档包 |
| 备份目标 | 独立 NAS 或异地目录 | `backend/data/backups/` 的异地副本 + Run 归档 |
| 操作员站 | 普通工控机 ×2（主/备） | 浏览器即可，无客户端安装 |
| 大屏/等候区屏 | 安卓电视盒 / 瘦客户端 | 打开 `/screen?kiosk=1...` 全屏即可 |

### 3.2 时钟同步

- 全系统统一时钟源：NTP（控制网内本地 NTP 服务器；有高频同步需求时上 PTP）
- `subsystems.yaml` 已有 `ntp_server` 配置项，投产时指向现场 NTP 服务器
- 所有样本以服务端时间戳为准，采集端时间戳仅作参考

### 3.3 可靠性与冗余

| 项 | 投产要求 |
|----|----------|
| 进程守护 | systemd `Restart=always`，异常退出 5s 内拉起 |
| 数据备份 | 系统自带定时备份（设置页可配）+ 备份目录异地同步（rsync/对象存储），**每月至少一次恢复演练** |
| UPS | 应用服务器与安全连锁控制站均挂 UPS，掉电时安全连锁按现场规程独立动作（不依赖软件） |
| 断网续传 | 采集层断链时本地缓存，恢复后补传（TSDB 迁移时实现） |
| 安全底线 | **急停与安全连锁永远是硬接线回路**，软件急停只是并联通道——架构评审时逐条确认 |

## 4. 数据架构细则

### 4.1 通道划分

| 通道 | 内容 | 频率 | 去向 | 保留 |
|------|------|------|------|------|
| 监控慢通道 | 风速/温度/压力/状态量 | 10Hz | TSDB | 原始 30 天 → 聚合 10 年 |
| 测量快通道 | 天平六分量/压力脉动/声学 | 1k~100kHz | Run 文件（HDF5） | 按项目合同，一般 ≥5 年 |
| 业务数据 | 用户/项目/订单/排程/审计/报告 | — | SQLite | 永久，纳入备份 |
| 日志 | 运行日志/审计日志 | — | 轮转文件 + 库 | 审计 ≥3 年 |

### 4.2 写入纪律（TSDB 迁移时执行）

- 批量异步写：攒批 500~1000 条/批，严禁逐条 INSERT
- 按时间分区，过期删分区而非 DELETE
- 每条样本带质量标志位（现有 `quality` 字段沿用）
- 查询只走「时间范围 + 聚合」，禁止全表扫描

### 4.3 迁移路径（不改业务代码）

适配器层已隔离数据访问（`app/services/store.py` 集中所有 SQL），迁移时：

1. 新增 TSDB 写入通路（store 层加实现，接口签名不变）
2. 遥测读路径（历史曲线/大屏趋势）切换数据源
3. 双写并行观察 1~2 周，校验一致后下线 SQLite 遥测表

## 5. 联调阶段计划

### 5.1 子系统接入流程（每个子系统走一遍）

1. `backend/config/subsystems.yaml`：该子系统 `mode: real`，核对 `endpoint` 与点表（tags）
2. 实现/补全 `app/adapters/real/` 对应协议适配器（按 `app/contracts/icd.py` 契约）
3. 前端子系统页跑「连通性测试」
4. 点位核对：逐点比对现场值与系统显示值（含单位、量程、方向）
5. 命令核对：先无负载点动，再带载；确认 `min_role` 权限与确认弹窗文案符合现场规程
6. 联锁验证：急停、门禁、故障注入——**先硬接线回路，后软件链路**

### 5.2 联调 Checklist（摘要）

- [ ] 12 个子系统全部 real 模式连通，`force_simulation=false`
- [ ] 总控台各读数与现场仪表比对误差在允许范围
- [ ] 风速闭环：设定→爬升→稳定→停止 全流程
- [ ] 风速程控阶梯剖面在真机上执行一个完整循环
- [ ] 试验矩阵单工况执行 + 数据落库 + 报告生成
- [ ] 急停（顶栏软件急停 + 现场硬急停）双通道验证
- [ ] 断网恢复：拔插控制网网线，系统告警→恢复→数据补齐
- [ ] 备份与恢复演练各一次
- [ ] 客户账号数据隔离抽查（只能看自己订单）

## 6. 试运行与投产验收

### 6.1 试运行（建议 4~8 周）

| 指标 | 目标 |
|------|------|
| 可用性 | ≥99.5%（计划外停机 < 3.6h/月） |
| 遥测链路 | WS 延迟 < 500ms，丢点率 < 0.1% |
| 命令可靠性 | 下发成功率 100%，审计记录完整 |
| 数据完整性 | 抽查 Run：原始文件 + 元数据 + 报告三者齐全 |
| 备份 | 自动备份成功率 100%，恢复演练通过 |

### 6.2 投产前必须关闭的事项

- [ ] JWT 密钥更换为随机强值（`WTCS_JWT_SECRET`）
- [ ] 四个内置测试账号密码全部更换，登录页「测试账号」快捷填充区块移除（`LoginPage.tsx` 顶部 TEST_ACCOUNTS）
- [ ] 遥测链路迁 TSDB，降采样策略生效
- [ ] HTTPS 启用（nginx 终止 TLS）
- [ ] CORS 来源收紧为正式域名
- [ ] 安全连锁硬接线回路第三方验收签字
